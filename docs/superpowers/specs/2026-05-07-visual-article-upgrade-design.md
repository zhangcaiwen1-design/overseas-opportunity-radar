# 精选稿成品化视觉升级设计稿

## 目标
把当前已经完成结构化案例拆解的精选稿，升级成更接近可直接发布的视觉成品稿：接入 GPT Image-2 主视觉图，保留来源截图作为证据素材，并把 HTML 页面升级为更有高级杂志感的专题页面。

## 背景
当前精选稿已经完成内容结构升级，具备：
- 项目介绍
- 运作模式 / 协作方式
- 为什么值得看
- 国产化路径
- 变现实操
- 内容传播角度

同时也已经具备：
- `materials/*.png` 来源截图素材
- `selected/*.png` 成稿预览图
- 基础杂志风 HTML + CSS

但现状距离“成品稿”还有明显差距：
- 首屏仍然更像程序生成页面，而不是专题封面
- 没有 GPT Image-2 主视觉图
- 来源截图只是素材拼图，还不是编辑化证据模块
- 页面排版层次还不够强，成品感不足

## 本次设计范围
范围内：
- 为每篇精选稿接入 GPT Image-2 主视觉图
- 将主视觉图纳入精选稿首屏
- 保留并重组来源截图为证据导览区
- 升级 HTML 页面结构与文字排版
- 保持 Markdown 与 HTML 内容一致，但重点提升 HTML 成品感
- 保持失败可降级，daily 流程不中断

范围外：
- 每篇自动生成多张辅助图的完整系统
- 视频流程同步消费 GPT Image-2 主视觉
- 推送渠道的富媒体适配
- 复杂人工挑图后台
- 完整视觉工作台

## 成品稿目标形态
升级后的一篇精选稿应包含三层：

### 1. 主视觉层
由 GPT Image-2 生成，默认每篇 1 张。

职责：
- 把抽象项目机会翻译成可感知的商业画面
- 拉起整页的成品感
- 为后续公众号封面、视频封面提供统一视觉基底

### 2. 证据素材层
继续使用现有 `materials/*.png` 来源截图。

职责：
- 证明案例来源真实存在
- 给正文拆解提供“不是空想”的证据感
- 为后续视频和二次创作保留真实素材

### 3. 正文排版层
继续使用结构化案例拆解内容，但升级版式和页面层次。

职责：
- 把项目讲清楚
- 把机会讲清楚
- 让整篇内容更像编辑整理后的专题稿，而不是自动生成页面

## 页面结构设计
精选稿 HTML 页面建议采用以下顺序：

### 1. 封面区
包含：
- 来源标签
- 主标题
- 一句话导语
- GPT Image-2 主视觉图

目标：
- 第一屏就具备栏目感、封面感、主题感
- 一眼看上去更像可直接发布的专题稿

### 2. 证据导览区
包含：
- 来源截图拼图或单张导览图
- 简短说明文案，例如“本篇拆解基于真实海外项目页面与公开信号”

目标：
- 让读者明确这篇内容不是凭空创作
- 把“素材拼图”升级为编辑化证据模块

### 3. 正文主体区
继续使用当前已确认的内容结构：
- 项目介绍
- 运作模式 / 协作方式
- 为什么值得看
- 国产化路径
- 变现实操
- 内容传播角度
- 验证步骤（可选）

目标：
- 按不同内容类型使用不同排版语气
- 让“项目介绍”更像导入，“运作模式”更像链路，“变现实操”更像行动建议

### 4. 收尾区
可包含：
- 更适合公众号还是抖音的传播切口
- 这条案例更像工具机会、流程机会、前台生意机会还是底座封装机会

目标：
- 为后续分发留下明确出口

## GPT Image-2 主视觉策略

### 1. 风格基线
主视觉默认走：
- 高级商业杂志封面感
- 温暖、可信、真实商业氛围
- 不使用黑金、赛博、廉价未来感

如果项目本身非常抽象，则允许补入：
- 商业场景插画感
- 人物、门店、工作台、流程动作等更易理解的经营线索

### 2. 画面职责
主视觉不是来源截图替代品，也不是软件界面复刻图。

它的职责是：
- 把机会主题翻译成能被用户一眼理解的经营场景
- 拉起整页的高级感与封面感
- 和正文内容形成统一视觉叙事

### 3. 视觉 brief 构成
主视觉 prompt / brief 至少应来自这些信息：
- 项目类型
- 主要经营场景
- 画面重点
- 风格方向
- 应避免的视觉误区

即：
- 工具增强型 → 更偏工作台、屏幕、效率动作
- 工作流协作型 → 更偏协作场景、任务流、角色分工
- 业务前台型 → 更偏客户承接、门店、服务台、成交感
- 能力底座型 → 更偏后台控制面、业务支撑、多系统协同的隐喻表达

### 4. 使用规则
第一版默认每篇保底尝试生成 1 张主视觉图。

辅助图策略：
- 不做全量强制
- 仅当项目特别适合时再补充
- 第一版不把辅助图作为核心交付物

## 数据流设计
当前精选稿链路需要升级为：

1. 采集原始机会信号
2. 筛出精选案例
3. 生成结构化案例分析结果
4. 基于分析结果生成主视觉 brief
5. 调用 GPT Image-2 生成主视觉图
6. 继续保留或复用 `materials/*.png` 来源截图
7. 将“主视觉 + 来源素材 + 正文分析结果”一起交给 HTML 渲染器
8. 输出成品 HTML / Markdown
9. 继续输出 `selected/*.png` 成稿预览图

### 顺序原则
主视觉图必须在页面渲染前生成。

原因：
- 它是首屏组成部分，不是后补附件
- 只有先生成，页面才能从结构上围绕它设计

## 数据结构建议
在当前精选稿分析结果之外，新增“视觉资产信息”层，至少包含：
- 主视觉图路径
- 主视觉 brief 摘要或 prompt
- 当前文章可用的来源截图列表
- 是否成功生成主视觉
- 降级状态

这样 HTML 渲染器接收的不再只是纯文案，而是：
- 结构化内容
- 主视觉图
- 来源证据图
- 可能存在的辅助图（未来扩展）

## 降级策略
虽然用户希望减少来回确认并快速推进，但 daily 流程仍必须可降级。

要求：
- GPT Image-2 主视觉生成失败时，整篇文章仍可生成
- 主视觉缺失时，页面退化成“无主视觉但有来源图 + 正文”的版本
- 来源截图缺失时，页面仍可生成，但证据区可省略或变轻量
- 不允许因为单篇图片失败导致整次 `npm run daily` 失败

## 视觉气质约束
页面气质统一为：
- 温暖
- 可信
- 真实商业感
- 高级但不浮夸
- 传统小老板也能接受

明确避免：
- 黑金风
- 过度赛博
- 强科技发布会视觉
- 廉价 AI 图感

## 第一版最小可用范围
这次第一版只做最重要的部分：
- 每篇精选稿默认尝试生成 1 张 GPT Image-2 主视觉
- 主视觉进入首屏
- 来源截图升级为证据导览区
- HTML 页面升级成更像专题成品稿
- `selected/*.png` 基于新版页面继续输出
- 所有流程都保留失败降级能力

暂不做：
- 每篇自动多张辅助图
- 多套视觉主题自动切换
- 视频同步消费主视觉
- 富媒体推送端适配
- 人工挑图后台

## 实施边界
本次只增强精选稿成品化输出，不修改：
- 机会池结构
- 视频结构
- 评分与筛选逻辑
- 推送逻辑
- 来源截图采集能力本身

## 验收标准

### 1. 成品感明显提升
打开任意精选稿 HTML 时，第一感受应从“自动生成测试页”变成“已编辑整理的专题成品稿”。

### 2. 大多数精选稿能带 1 张主视觉
不是要求百分之百成功，但大多数正常案例应能产出主视觉图并进入首屏。

### 3. 主视觉失败不影响整次 daily
即使个别图片生成失败，文章仍应完成输出。

### 4. 来源截图仍保留真实感
不能因为主视觉升级而丢掉来源证据层。

### 5. HTML 页面层次明显更强
至少在首屏、证据区、正文层次和收尾区四个部分上能看出结构变化。

### 6. daily 流程仍可日更跑通
升级后仍应支持本地优先、自动出稿和预览图产出。

## 为什么这一步值得现在做
因为当前内容结构已经从模板摘要升级为案例拆解，下一步最缺的不是再多几个文案字段，而是让这些内容真正长成“能直接发”的成品页面。

只有把：
- 结构化内容
- GPT Image-2 主视觉
- 来源截图证据层
- 高级杂志风页面排版

组合起来，精选稿才会真正接近用户要的“成品级图文”。

## 下一步实施方向
下一步实施计划应围绕四块：
1. 新增主视觉资产层与 GPT Image-2 生成链路
2. 生成并保存每篇精选稿的主视觉图
3. 升级 HTML 首屏、证据区和正文章节版式
4. 增加降级测试、成稿测试与 README 说明
