# 图文截图素材接入设计稿

## 目标
把真正的来源页面截图素材接入精选文章成稿流程，让精选文章具备“顶部拼图总览 + 正文单图来源图”的图文成品形态，更适合直接用于公众号与内容分发。

## 关键事实修正
当前代码里的 `selected/*.png` 并不是“采集来源页面截图”，而是“精选文章 HTML 成稿截图”。

这意味着：
- 它们可以作为成稿预览图
- 但不能充当“原始来源证据图”
- 也不适合直接再嵌回同一篇文章里，否则会出现两次渲染甚至自引用问题

所以本次正确方案不是直接消费 `selected/*.png` 作为正文证据图，而是新增一层真正的来源素材截图产物。

## 背景
当前流水线已经可以完成：
- 采集海外机会信号
- 标准化筛选出精选与机会池
- 为精选文章生成 Markdown 与 HTML
- 为精选与机会池生成成稿截图 `selected/*.png`、`pool/*.png`

但现在缺少的是“来源素材截图层”。也就是还没有把真实机会来源页截图保存下来，供文章、视频、后续二次创作复用。

## 本次设计范围
范围内：
- 为精选机会新增来源素材截图产物
- 精选文章顶部使用来源素材截图拼图
- 精选文章正文引用当前案例自己的来源素材图
- 保持机会池输出风格不变
- 保持本地优先和可测试性

范围外：
- 视频时间线如何消费来源素材截图
- GPT Image-2 生图混排
- 外部网络图片/视频素材拉取
- 推送渠道富媒体排版适配

## 新的产物结构
在当前每日输出目录下新增：
- `materials/*.png` — 来源页面素材截图，仅用于后续图文/视频复用

保留现有：
- `selected/*.html` — 精选文章 HTML
- `selected/*.md` — 精选文章 Markdown
- `selected/*.png` — 精选文章页面截图
- `pool/*.html` — 机会池简报 HTML
- `pool/*.png` — 机会池简报截图

这样职责会更清晰：
- `materials/*.png` 是原始素材层
- `selected/*.png` / `pool/*.png` 是成稿预览层

## 设计原则

### 1. 原始素材层与成稿层分离
来源截图和文章成稿截图不是一回事，必须拆开保存，避免后续渲染循环引用。

### 2. 精选文章增强，机会池不加重
本次只增强精选文章，不让机会池承担长文级视觉结构。

### 3. 最小侵入接入现有流水线
不改评分、不改筛选、不改推送，只在精选编排与渲染层之间补一个“来源素材截图”步骤。

### 4. 本地优先不能被破坏
当信号来自 `sample` 或来源页不可访问时，流水线仍要成功；只是该条没有来源素材图，不得让 `npm run daily` 失败。

## 核心方案
采用三层结构：

### 第一层：来源素材截图采集
当精选机会确定后，针对每条精选的 `canonicalUrl` 尝试抓取页面截图，输出到 `materials/<slug>.png`。

仅对这些条件满足的机会尝试抓取：
- 不是 `sample` 来源
- URL 是有效的 http/https 地址
- 未被显式禁用截图采集

如果抓取失败，则跳过该条来源图，不中断整次 daily 流程。

### 第二层：精选文章顶部拼图
精选文章顶部拼图不再使用 `selected/*.png`，而是使用本批次可用的 `materials/*.png` 做总览拼图。

作用：
- 第一屏直接展示今天的真实机会来源面貌
- 给图文成稿更强的“不是空想、是有来源的”感受

### 第三层：正文单图来源图
每篇精选文章正文中引用自己对应的 `materials/<slug>.png`，作为当前案例的来源图。

作用：
- 强化来源可信度
- 方便后续口播、图文二次改写时回看原始页面
- 满足“采集时截图作为素材”的真实需求

## 数据与渲染结构
现有 `OpportunitySignal` 已经有：
- `title`
- `canonicalUrl`
- `source`

现有 `WrittenOpportunity` 需要新增可选图片字段，例如：
- 当前文章来源图
- 当前批次拼图图片集合

现有 `DailyArtifact` 也需要新增来源素材图路径字段，便于结果层和测试层引用。

渲染流程应调整为：
1. 先选出精选
2. 为精选准备来源素材图路径
3. 尝试抓取来源素材图
4. 把素材图信息传给 HTML/Markdown 渲染器
5. 再生成精选文章 HTML/Markdown
6. 最后继续生成文章成稿截图 `selected/*.png`

这样可以避免“文章里引用的图片文件还没生成”这一顺序问题。

## 页面结构建议
精选文章页面结构调整为：
1. 标题区
2. 顶部拼图区（来源素材图总览）
3. 海外信号说明
4. 当前案例来源图区
5. 国产化落地路径
6. 变现方式
7. 验证路径

## 测试策略
至少覆盖：
- 精选文章 HTML 中出现拼图模块标记
- 精选文章 HTML 中出现当前文章来源图引用
- 机会池 HTML 中不出现拼图模块
- `sample` 信号下 daily 流程仍成功
- README 同步描述 `materials/*.png` 的职责

测试不校验像素结果，只校验结构、路径和流程是否正确。

## 风险与控制

### 风险 1：外部页面访问失败导致流程变慢或失败
控制方式：仅对可访问的真实 URL 尝试抓图；失败时跳过，不让整条流水线失败。

### 风险 2：来源素材图为空时文章结构变形
控制方式：拼图和正文来源图区都按“有图才渲染”处理，没图时自动省略该区块。

### 风险 3：把成稿截图和来源截图继续混用
控制方式：README、类型命名、目录命名都明确分成 `materials` 与 `selected/pool` 两层。

## 为什么这才是正确的下一步
因为用户要的是“采集项目时顺手把来源页截图保存为素材”，而不是把生成后的文章截图再塞回文章里。

只有先补上 `materials/*.png` 这一层，后面的：
- 图文成稿
- 视频素材复用
- 来源可信展示
- 后续内容二创

才会真正成立。
